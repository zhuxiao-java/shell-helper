# Shell Helper 技术架构文档

- 版本：v1.0
- 关联文档：[需求文档.md](./需求文档.md)
- 一句话概述：**Electron 桌面壳 + Vue3/Element Plus 前端 + Python 后端（协议与会话核心）**，前后端通过本机 HTTP + WebSocket 通信，本地 SQLite 持久化，系统 Keychain 保管密钥。

## 2. 系统整体架构

### 2.1 进程模型

Electron 采用多进程模型，配合独立 Python 后端进程：

```
┌──────────────────────────────────────────────────────────────┐
│                     Electron 应用                              │
│                                                                │
│  ┌────────────────┐        IPC         ┌───────────────────┐  │
│  │  Main Process  │◀──────────────────▶│ Renderer Process  │  │
│  │  (Node.js)     │   preload bridge   │ (Vue3 + Element)  │  │
│  │                │                     │                   │  │
│  │ - 窗口生命周期  │                     │ - UI 渲染         │  │
│  │ - spawn 后端    │                     │ - xterm.js        │  │
│  │ - 系统集成      │                     │ - 文件面板        │  │
│  │ - 自动更新      │                     │ - Pinia store     │  │
│  └──────┬─────────┘                     └─────────┬─────────┘  │
│         │                                         │            │
│         │  spawn (stdio)        HTTP / WebSocket  │            │
│         │                                         │            │
└─────────┼─────────────────────────────────────────┼────────────┘
          ▼                                          ▼
   ┌──────────────────────────────────────────────────────┐
   │            Python Backend (FastAPI + Uvicorn)          │
   │            监听 127.0.0.1:<随机端口> + Token            │
   │                                                        │
   │  ┌──────────┐ ┌──────────┐ ┌────────┐ ┌─────────────┐  │
   │  │ Session  │ │  File    │ │Transfer│ │  Host/Cred  │  │
   │  │ Manager  │ │ Service  │ │ Queue  │ │  Service    │  │
   │  └────┬─────┘ └────┬─────┘ └───┬────┘ └──────┬──────┘  │
   │       │            │           │             │         │
   │   Paramiko     SFTP/FTP     Worker池      SQLite      │
   │   PTY/SSH      pyftplib     asyncio      (加密)       │
   └───────┼────────────┼──────────┼─────────────┼─────────┘
           ▼            ▼          ▼             ▼
      [Remote SSH]  [Remote FS] [磁盘/网络]   [本地数据]
```

**关键点：**

1. **Main Process** 负责启动/守护 Python 后端，注入端口与 Token。
2. **Renderer Process** 不直接持有 Node 能力（`nodeIntegration=false`），所有本地操作经 `preload` 暴露的白名单 API 或直接访问本机 HTTP/WS。
3. **Python 后端** 是唯一与远端服务器、PTY、磁盘打交道的组件，集中管理所有连接。
4. 三者通过 **本机回环**，端口随机 + Bearer Token，避免被外部端口扫描利用。

### 2.2 三层职责划分

| 层 | 组件 | 职责 | 不做 |
| --- | --- | --- | --- |
| 展示层 | Vue 组件 | UI、交互、终端渲染 | 不写协议逻辑 |
| 应用层 | Electron Main、Pinia Store | 状态编排、系统集成 | 不直连远端 |
| 服务层 | Python FastAPI | SSH/SFTP/FTP/PTY、持久化、加密、传输调度 | 不关心 UI |

## 3. 前端架构

### 3.1 Electron 双进程

```
electron/
├── main/                 # 主进程
│   ├── index.ts          # 入口，创建窗口
│   ├── backend.ts        # 启动/停止 Python 后端，注入端口 token
│   ├── ipc/              # IPC handlers（窗口、对话框、系统命令）
│   ├── menu.ts           # 应用菜单
│   ├── updater.ts        # 自动更新
│   └── tray.ts           # 托盘（可选）
├── preload/
│   └── index.ts          # contextBridge 暴露安全 API
└── renderer/             # Vue3 应用（下节）
```

**后端进程通信协议**：Main 通过 spawn Python 可执行文件，读取后端在 stdout 打印的 `{"port":..., "token":...}` 握手行，随后经 IPC 传给渲染进程。渲染进程用返回的 `baseUrl + token` 建立 HTTP/WS 连接。

**Electron 安全基线：**

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`
- preload 仅通过 `contextBridge.exposeInMainWorld` 暴露最小 API
- 所有 IPC channel 走白名单常量表
- CSP 限制脚本来源，禁止远端 eval
- 外链一律用 `shell.openExternal`，禁止在渲染进程直接导航

### 3.2 渲染层目录结构

```
renderer/src/
├── main.ts                # Vue 应用入口
├── App.vue
├── api/                   # 后端接口的类型化封装
│   ├── http.ts            # axios 实例（注入 token）
│   ├── ws.ts              # WebSocket 客户端封装（终端 IO）
│   ├── hosts.ts
│   ├── sessions.ts
│   ├── files.ts
│   └── transfers.ts
├── stores/                # Pinia
│   ├── hostStore.ts
│   ├── sessionStore.ts
│   ├── transferStore.ts
│   ├── settingStore.ts
│   └── uiStore.ts
├── views/
│   ├── MainLayout.vue     # 三栏主布局
│   ├── HostPanel/         # 左侧主机树
│   ├── TerminalView/      # xterm 终端
│   ├── FileManager/       # 双栏文件
│   ├── TransferDrawer/    # 传输队列
│   └── Settings/
├── components/            # 通用组件
├── composables/           # useTerminal, useSftp, useWebSocket
├── styles/                # SCSS 变量、Element 主题、多主题
├── locales/               # i18n
└── router/
```

### 3.3 状态管理（Pinia）

| Store | 状态 | 说明 |
| --- | --- | --- |
| hostStore | hosts、groups、tags、filter | 主机树 |
| sessionStore | sessions[]、activeId、splits | 会话与标签 |
| fileStore | remoteCwd、localCwd、entries | 文件面板 |
| transferStore | queue[]、history[]、stats | 传输队列 |
| credentialStore | 内存凭据缓存（不落 localStorage） | 用完即弃 |
| settingStore | settings | 应用配置 |
| uiStore | theme、locale、panelSize | UI 偏好 |

**约定**：`sessionStore` 是终端与文件联动的枢纽——终端 PTY 解析到 `cd` 等指令后更新 `session.remoteCwd`，`fileStore` 通过 `watch` 自动刷新目录。

### 3.4 终端与文件联动机制

```
用户输入 →  xterm.js →  WS(二进制)  → Python PTY → 远端 shell
                                                    │
远端输出 ←  WS(二进制)  ←  Python 读取 PTY  ←───────┘
       │
       ├─▶ xterm 渲染
       └─▶ 前端 OSC 解析器：读取 \x1b]0;...\x07 (shell 提示标题)
                └─▶ 若含 CWD 信息 → 更新 fileStore → 文件面板刷新
```

推荐配合 `.bashrc` 里设置 `PROMPT_COMMAND` 发送 OSC 7 转义序列携带当前工作目录，实现精确联动。

## 4. 后端架构（Python）

### 4.1 目录结构

```
backend/
├── pyproject.toml
├── app/
│   ├── main.py            # FastAPI 实例 + 路由注册 + 握手输出
│   ├── config.py          # 端口、token、数据目录
│   ├── api/
│   │   ├── hosts.py
│   │   ├── credentials.py
│   │   ├── sessions.py
│   │   ├── terminals.py   # WebSocket
│   │   ├── files.py
│   │   ├── transfers.py
│   │   ├── snippets.py
│   │   └── settings.py
│   ├── core/
│   │   ├── security.py    # token 鉴权、加解密
│   │   ├── crypto.py      # AES-GCM + keyring
│   │   ├── db.py          # SQLAlchemy engine/session
│   │   └── events.py      # 进程内事件总线
│   ├── services/
│   │   ├── session_manager.py
│   │   ├── ssh_service.py     # Paramiko 封装
│   │   ├── sftp_service.py
│   │   ├── ftp_service.py
│   │   ├── telnet_service.py
│   │   ├── local_pty_service.py
│   │   └── transfer_service.py  # 队列/工作池
│   ├── models/            # SQLAlchemy ORM
│   ├── schemas/           # Pydantic
│   └── repositories/      # 数据访问层
├── alembic/               # 迁移
└── tests/
```

### 4.2 分层

```
API (routers)  →  Service (业务/协议)  →  Repository (DB)
                       │
                       └─▶ Core (crypto / security / events)
```

- **Router**：只做参数校验、鉴权、序列化，无业务逻辑。
- **Service**：协议实现、会话编排、传输调度。
- **Repository**：唯一的 SQL 出入口。

### 4.3 会话与连接管理

`SessionManager` 单例：

```python
sessions: dict[str, Session]         # session_id -> Session
host_pool: dict[str, SSHConnection]  # host_key -> 复用的底层连接
```

- **Session** 生命周期：`OPENING → ACTIVE → CLOSING → CLOSED / ERROR`
- **同主机复用**：一个 SSH host 可承载多 channel（terminal + sftp），减少握手开销
- **跳板链路**：`jump_chain = [j1, j2]` → 用 j2 的 transport 作为 sock 打开目标
- **异常清理**：底层 socket 断开时通过 `events.emit('session.closed')` 通知，前端 WS 收到 close frame

### 4.4 终端 IO（WebSocket）

- 一个前端终端标签 = 一条 WebSocket：`/api/terminals/{session_id}/ws`
- **帧协议**：
  - 二进制帧：PTY 原始字节（输入/输出）
  - 文本帧：JSON 控制消息 `{type: "resize", cols, rows}` / `{type:"ping"}`
- 后端用 `asyncio` + `run_in_executor` 包裹 Paramiko 阻塞读，向 WS 推流
- 窗口大小变化通过前端 fit addon 计算，发送 `resize` 控制帧

### 4.5 文件服务

| 操作 | SFTP 实现 | FTP 实现 |
| --- | --- | --- |
| list | `sftp.listdir_attr` | `nlst` + `MLSD` |
| download | `sftp.get` / prefetch | `retrbinary` + REST |
| upload | `sftp.put` | `storbinary` + REST |
| mkdir | `sftp.mkdir` | `mkd` |
| rename | `sftp.rename` | `RNFR/RNTO` |
| delete | `sftp.remove` | `dele` |
| chmod | `sftp.chmod` | `SITE CHMOD` |

大目录采用 **分页 + 流式**：`GET /api/files?path=...&offset=0&limit=500`。

### 4.6 传输队列

```
TransferService
 ├── PriorityQueue (待办)
 ├── Worker Pool (asyncio tasks, 默认并发 3)
 ├── RateLimiter (令牌桶, 全局 & 单任务)
 └── ProgressBus (WS 广播进度事件)
```

- 任务状态：`PENDING → RUNNING → PAUSED → DONE / FAILED / CANCELED`
- 断点续传：SFTP 记录已传 offset，重启后 `seek` 续传；FTP 用 REST 命令
- 失败重试：指数退避 `1s/2s/4s`，最多 N 次
- 进度事件通过 `/api/transfers/ws` 广播给前端队列面板

### 4.7 凭据与加密

```
主密钥(MK) ── 存于 keyring(系统) 或由"主密码+KDF"派生
       │
       ▼
DEK(数据密钥) ── 用于 AES-256-GCM 加解密具体凭据
       │
       ▼
SQLite.encrypted_credentials  (ciphertext + nonce + tag)
```

- 优先使用 `keyring` 存主密钥（macOS Keychain / Windows DPAPI / Linux libsecret）
- 无系统 Keychain 时降级为主密码模式：PBKDF2-HMAC-SHA256(600k 迭代) 派生主密钥
- 明文凭据永不写入磁盘和日志；API 返回时 `credential.value` 恒为 `null`，仅在建立连接时后端内部使用

### 4.8 数据模型（关键表）

```sql
groups(id, name, parent_id, order)
hosts(id, name, group_id, protocol, host, port, username,
      auth_type, credential_id, key_path, jump_host_ids, tags, created_at, updated_at)
credentials(id, label, type, ciphertext, nonce, key_path, created_at)
sessions(id, host_id, type, status, remote_cwd, opened_at, closed_at)
transfer_tasks(id, session_id, direction, remote_path, local_path,
               size, transferred, state, speed, offset, error, created_at, finished_at)
snippets(id, group, title, content, params)
known_hosts(id, host, port, fingerprint, added_at)
```

## 5. 前后端通信契约

### 5.1 传输方式

| 场景 | 方式 | 说明 |
| --- | --- | --- |
| 常规 CRUD | HTTP REST(JSON) | 主机、凭据、片段、设置 |
| 文件列表/操作 | HTTP REST(JSON) | 元数据类 |
| 上传/下载 | HTTP(流式) | `multipart/form-data`；下载支持 Range |
| 终端 IO | WebSocket(二进制) | 低延迟 |
| 传输进度/会话事件 | WebSocket(服务端推送) | SSE 作为降级方案 |

### 5.2 REST API 摘要

```
GET    /api/hosts              列表
POST   /api/hosts              新建
GET    /api/hosts/{id}
PUT    /api/hosts/{id}
DELETE /api/hosts/{id}
POST   /api/sessions           打开会话 {hostId, type}
DELETE /api/sessions/{id}      关闭会话
GET    /api/files?sid=&path=   列目录
POST   /api/files/mkdir
POST   /api/files/rename
POST   /api/files/delete
GET    /api/files/download?sid=&path=   下载（支持 Range）
POST   /api/files/upload                上传（multipart）
GET    /api/transfers                   队列
POST   /api/transfers/{id}/pause
POST   /api/transfers/{id}/resume
DELETE /api/transfers/{id}
GET    /healthz                后端健康检查（Electron 探活）
```

### 5.3 WebSocket 端点

```
WS /api/terminals/{session_id}/ws    终端 IO
WS /api/transfers/ws                 传输进度事件
WS /api/events/ws                    全局事件(会话断开等)
```

### 5.4 鉴权

- 所有 HTTP/WS 请求头携带 `Authorization: Bearer <token>`
- Token 由 Electron Main 在启动后端时生成，仅存内存
- 后端仅 `bind 127.0.0.1`，不对外网暴露

## 6. 数据流示例

### 6.1 双击主机建立 SSH 会话

```
[用户双击主机]
   │  Renderer: hostStore.connect(hostId)
   ▼
[HTTP POST /api/sessions {hostId,type:terminal}]
   │  Router → SessionService
   │  ├─ Crypto 解密凭据（keyring 取主密钥）
   │  ├─ Paramiko 建连（含跳板链）
   │  ├─ invoke_shell → 得到 channel
   │  └─ 注册到 SessionManager，返回 sessionId
   ▼
[Renderer 用 sessionId 建立 WS /api/terminals/{id}/ws]
   │  xterm.js 挂载
   ▼
[用户输入 → WS 二进制 → PTY → 远端；输出反向回显]
```

### 6.2 拖拽上传文件

```
[拖拽文件到文件面板]
   │  Renderer 读取文件元信息
   ▼
[HTTP POST /api/transfers {sessionId, localPath, remotePath, dir:up}]
   │  TransferService 入队，返回 taskId
   ▼
[Worker 领取任务 → SFTP.put 流式上传]
   │  每 200ms 通过 /api/transfers/ws 推送进度
   ▼
[TransferDrawer 实时刷新进度条；完成后 fileStore 刷新目录]
```

## 7. 打包与分发

### 7.1 Python 后端打包

- PyInstaller 将 `backend/` 打成单文件可执行程序：
  - Windows：`shell-helper-backend.exe`
  - macOS：`shell-helper-backend`（分别出 x86_64 / arm64）
  - Linux：`shell-helper-backend`
- 产物放入 Electron 的 `resources/backend/<platform>/`

### 7.2 Electron 打包

- `electron-builder` 读取 `extraResources` 把后端可执行文件、图标等打入
- 输出：
  - Windows：NSIS `.exe` + 便携 `.zip`（代码签名）
  - macOS：`.dmg` + `.zip`（Notarize 公证）
  - Linux：`.AppImage` + `.deb`
- 前端 `dist/` 静态资源随包

### 7.3 启动时序

```
Electron Main 启动
  → 定位 resources/backend/<platform> 可执行
  → spawn（传入 --port=0 随机端口, --data-dir=userData）
  → 读 stdout 握手行获取真实 port + token
  → 轮询 /healthz 直到 200
  → 创建 BrowserWindow，经 IPC 下发 port+token
  → 渲染进程加载，初始化 api 客户端
应用退出：
  → Main 发送 SIGTERM / 调 /shutdown
  → 后端优雅关闭所有会话、flush 数据库
  → 确认进程退出后 app.quit()
```

### 7.4 自动更新

- `electron-updater` 检查更新（含前端与 Electron）
- 后端可执行文件作为资源随整包更新，避免独立升级不一致
- 更新前提示，采用下次启动替换策略

| 层级 | 工具 | 范围 |

## 10. 关键设计决策（ADR 摘要）

| # | 决策 | 备选 | 选择理由 |
| --- | --- | --- | --- |
| D1 | 协议逻辑放 Python 后端 | Node 端用 ssh2.js | 用户要求 Python；Paramiko 成熟；便于复用与脚本扩展 |
| D2 | 前后端用 HTTP+WS 而非纯 IPC | Electron IPC 全程代理 | 解耦、易测试、后端可独立运行/远程化 |
| D3 | Vue3 + Element Plus | Vue2 + Element UI | Element UI 停更于 Vue2；Plus 是其延续 |
| D4 | 本地 SQLite + keyring 加密 | 明文 JSON | 安全要求；结构化查询 |
| D5 | PTY 输出走 WS 二进制 | base64 JSON | 低延迟、低带宽 |
| D6 | 后端仅监听 127.0.0.1 + token | 无鉴权 | 防本机端口扫描 |
