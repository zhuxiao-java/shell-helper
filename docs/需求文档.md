# Shell Helper 桌面端产品需求文档（PRD）

- 项目名称：Shell Helper
- 版本：v1.0
- 文档状态：草稿
- 技术形态：Electron + Vue + Element UI（前端） / Python（后端服务）

---

## 1. 项目背景

开发、运维人员日常需要频繁使用 SSH 终端、SFTP/FTP 文件传输等工具。现有工具（如 Xshell、FinalShell、FileZilla、Termius）存在以下痛点：

1. **工具割裂**：终端与文件管理通常是两个独立工具，切换成本高。
2. **联动困难**：在终端里改了一个文件，需要手动刷新文件列表才能下载/查看。
3. **多协议支持不完整**：多数工具要么专注 SSH，要么专注 FTP，很少同时覆盖 SFTP、FTP、Shell。
4. **可扩展性差**：现有工具多为闭源，难以集成团队自研脚本、监控面板等能力。

基于以上背景，计划开发一款集 **SFTP + FTP + Shell（SSH/Telnet/本地终端）** 于一体的跨平台桌面端工具，前端使用 Electron + Vue + Element UI 提供现代化 UI，后端使用 Python 承担协议实现、会话管理和数据处理，通过本地 IPC/HTTP/WebSocket 通信，实现"终端 + 文件"联动的一体化体验。

## 2. 目标与范围

### 2.1 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 提供稳定可靠的 SSH/SFTP/FTP 客户端 | 会话成功率 ≥ 99% |
| 实现终端与文件管理的双向联动 | 终端 cd 时文件面板自动同步路径 |
| 支持多标签、多会话并行 | 同时 ≥ 20 个会话稳定运行 |
| 支持凭据集中管理与加密存储 | 密码/私钥本地加密存储，无明文 |
| 跨平台 | Windows 10+、macOS 12+、主流 Linux 发行版 |

### 2.2 本期范围（v1.0 MVP）

**包含：**

- SSH 终端（含密码、公钥、私钥、跳板机）
- Telnet 终端
- 本地终端（bash / zsh / PowerShell / cmd）
- SFTP 文件浏览、上传、下载、重命名、删除、新建目录
- FTP 文件浏览、上传、下载、重命名、删除、新建目录
- 主机管理（分组、标签、搜索、导入/导出）
- 会话管理（多标签、拆分窗口、会话恢复）
- 凭据管理（密码、私钥、SSH Agent）
- 文件本地/远端编辑器（调用系统编辑器 + 内置编辑器）
- 传输队列（暂停、续传、失败重试、限速）
- 常用命令片段收藏与一键执行
- 操作日志与传输日志

**不包含（v2.0 或后续考虑）：**

- RDP / VNC 远程桌面
- Kubernetes 集成
- 数据库客户端
- 团队云端同步与共享凭据
- AI 命令建议（预留接口）
- 插件市场

## 3. 用户角色与使用场景

### 3.1 目标用户

| 角色 | 主要诉求 |
| --- | --- |
| 后端/全栈开发工程师 | 登录服务器调试、查看日志、上传部署包 |
| 运维工程师 (SRE/DevOps) | 批量管理服务器、监控、脚本执行 |
| 测试工程师 | 环境准备、日志拉取 |
| 数据/算法工程师 | 上传下载数据集、远程跑脚本 |
| 学生/爱好者 | 学习 Linux、连接树莓派/云服务器 |

### 3.2 典型用户故事

**US-01 建立 SSH 会话**
> 作为开发者，我希望在主机列表双击一台服务器，就能自动使用保存的密码打开终端会话，避免每次手动输入。
> 验收：从双击到新终端可输入 ≤ 2 秒；失败时有明确错误提示。

**US-02 终端与文件联动**
> 作为运维，我希望在终端里 `cd /var/log` 时，左侧文件面板自动切到 `/var/log`，方便直接下载日志。
> 验收：终端执行 `cd` 后，文件面板路径在 1 秒内同步。

**US-03 大文件断点续传**
> 作为算法工程师，我需要一个 2GB 训练包上传中断后能自动续传，而不是从头再来。
> 验收：手动中断进程后重启客户端，队列中的任务能从断点继续。

**US-04 凭据安全**
> 作为企业用户，我希望保存的密码在硬盘上以加密形式存储，即使数据库被拷贝也无法读取明文。
> 验收：使用主密码或系统 Keychain 加密；导出配置时可选择不包含敏感字段。

**US-05 命令片段**
> 作为运维，我希望把常用的 `docker ps`、`tail -f xxx.log` 保存成"收藏"，在任意会话中一键运行。
> 验收：支持分组、参数占位符、快速搜索。

**US-06 跳板机**
> 作为开发者，我需要通过堡垒机访问内网机器，希望配置一次即可，不用每次都手动 `ssh jump -> ssh internal`。
> 验收：主机配置支持指定"跳板链路"，可多级嵌套。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
| --- | --- |
| 冷启动 | ≤ 3 秒（首个窗口可交互） |
| 打开会话 | 建立 SSH 连接（不含网络延迟） ≤ 800ms |
| 终端输入回显延迟 | ≤ 30ms（本地环回） |
| 大文件列表（10k+ 项） | 首屏渲染 ≤ 1.5s，虚拟滚动 |
| 空闲内存 | 单会话 ≤ 200MB，10 会话 ≤ 700MB |
| 传输带宽利用率 | ≥ 90%（同网段千兆内网） |

### 5.2 可靠性

- 客户端崩溃不影响远端会话（可选启用服务端 `tmux`/`screen` 集成，v2）
- 网络抖动 5 秒内自动恢复；超过则明确提示
- 传输队列任务元数据持久化，重启后可继续

### 5.3 兼容性

| 平台 | 最低版本 |
| --- | --- |
| Windows | Windows 10 x64 1809+ |
| macOS | macOS 12 Monterey（Intel & Apple Silicon） |
| Linux | Ubuntu 20.04 / Debian 11 / Fedora 36+（.deb / .rpm / AppImage） |

### 5.4 安全

- 所有敏感数据加密存储，禁止明文日志
- Electron 侧关闭 `nodeIntegration`，通过 preload + IPC 白名单通信
- Python 后端仅监听 `127.0.0.1`，随机端口 + Token 鉴权
- 依赖库定期安全扫描（npm audit / pip-audit）

### 5.5 可维护性

- 前后端分离，接口通过 OpenAPI/IPC 协议文档约束
- 核心模块单测覆盖率 ≥ 60%，协议层 ≥ 80%
- 遵循 Conventional Commits

### 5.6 可用性 / 无障碍

- 键盘可完成 90% 常规操作
- 支持深色主题
- 中/英文双语，i18n 框架

### 5.7 可安装/可升级

- 支持自动更新（Electron-updater），带更新说明
- Windows 提供安装包 `.exe`（NSIS）+ 便携版 `.zip`
- macOS `.dmg`（含公证）
- Linux `.AppImage` + `.deb`

## 7. 数据需求

### 7.1 主要实体

- **Host（主机）**：id、name、group、tags、protocol、host、port、username、authType、credentialId、jumpHostIds、defaultAction、createdAt、updatedAt
- **Group（分组）**：id、name、parentId、order
- **Credential（凭据）**：id、label、type(password/privkey/agent)、encryptedValue、keyPath、passphraseRef
- **Session（会话）**：id、hostId、type(terminal/file)、openedAt、closedAt、remoteCwd、exitReason
- **TransferTask（传输任务）**：id、sessionId、direction、remotePath、localPath、size、transferred、state、speed、startedAt、finishedAt、error
- **Snippet（命令片段）**：id、group、title、content、params
- **LogEntry**：id、level、scope、message、ts

### 7.2 存储

- 结构化数据：SQLite（本地文件，加密）
- 敏感字段：AES-256-GCM 加密的字段 + 系统 Keychain 存主密钥
- Blob（缓存/临时文件）：`userData/cache/`
- 日志：`userData/logs/`

### 7.3 导入导出

- 主机与片段导出为 `.shellhelper.json`，可选择"不含密码"
- 从 mremoteng（CSV/RDF）、Termius（JSON）导入

## 8. 接口需求（简版，详见架构文档）

- Python 后端以 HTTP + WebSocket 提供服务
- 主要 API 分组：
  - `/api/hosts` 主机 CRUD 与分组
  - `/api/credentials` 凭据（不返回明文）
  - `/api/sessions` 会话生命周期
  - `/api/terminals/:id/ws` 终端 IO（WebSocket + 二进制帧）
  - `/api/files` 文件列表、上传、下载、rename、mkdir、delete
  - `/api/transfers` 队列管理
  - `/api/snippets` 命令片段
  - `/api/settings` 应用设置
  - `/api/logs` 日志查询
- Electron 主进程通过本地 HTTP/WS 与 Python 后端交互，通过 IPC 与渲染进程交互

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Electron 内存占用高 | 用户投诉卡顿 | 会话虚拟化、渲染层 xterm.js 复用、及时释放 PTY |
| 各平台 Keychain API 差异 | 凭据存储方案复杂 | 抽象 CredentialProvider 接口，多后端 fallback 到主密码模式 |
| FTP 明文协议安全性 | 用户数据被嗅探 | UI 显著提示"不加密"，推荐 SFTP；FTP over TLS 支持 |
| Python 后端与 Electron 生命周期耦合 | 僵尸进程 | Electron 主进程 spawn/detach 时写入 PID，退出前主动 kill |
| 私钥格式多样（PPK、PuttyGen 生成） | 部分用户无法登录 | 集成 `puttykey` 转换；引导用户使用 OpenSSH 格式 |
| 大目录列出阻塞 | UI 无响应 | Python 端流式返回 + 前端虚拟列表 |
